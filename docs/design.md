# Устройство MVP

```text
comb-catalog.json
        │
        ▼
 Python planner ─────► plan.json / plan.lua
                           │
                           ▼
                    Lua executor (OpenOS)
                           │
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
  автоматические      задачи игроку       журнал линий
    мутации          и проверки МЭ        и операций
```

Python отвечает за проверяемые графовые расчёты. Lua получает компактный готовый
план и не решает глобальную задачу заново в каждом цикле.

## Модель графа

- Узел — вид пчелы.
- Гиперребро `(родитель A, родитель B) → результат` — рецепт мутации.
- Ребро `вид → сота` хранит тип продукции и базовый шанс.
- Пара родителей неупорядочена.

Глубина вида вычисляется фиксированной точкой:

`depth(result) = 1 + max(depth(parentA), depth(parentB))`.

План хранит выбранный рецепт каждого достижимого вида. Равенства разрешаются
детерминированно: глубина, число условий, ручная/автоматическая операция, UID.

## Учёт принцесс

Каждая конечная цель получает путь переноса одной линии от доступного стартового
вида. В режиме `collect` цель, уже лежащая на пути более поздней цели, не создаёт
отдельную линию. Затем добавляются вспомогательные пути для зависимостей, ещё не
посещённых основными линиями. Полученное число безопасно для выбранного плана,
но не включает случайные потери.

## Ручные задачи

Поддерживаются два типа:

- `advanced_mutation`: выбрать целевой результат в продвинутом мутатроне;
- `provide_drones`: положить запрошенные дроны финального вида в МЭ.

Результат ручной мутации принимается через выделенный контейнер, который должен
быть пуст до старта задачи. Это не позволяет принять старую матку того же вида за
новый результат. Галочка является командой проверить, а не подтверждением успеха.
