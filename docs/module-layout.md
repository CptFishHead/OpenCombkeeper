# Как построить модули OpenCombkeeper

## Минимальная схема

Одного транспозера недостаточно: после стороны МЭ-интерфейса остаётся пять граней,
а системе нужны три механизма и три контейнера. Минимальная установка состоит из
двух одинаково подключённых модулей.

```text
                         общая МЭ-сеть
                         │           │
                  МЭ-интерфейс   МЭ-интерфейс
                         │           │
                    [модуль A]   [модуль B]
                    транспозер   транспозер
                      │ │ │       │   │   │
                      │ │ │       │   │   └─ сундук источников дронов
                      │ │ │       │   └───── сундук готовых производителей
                      │ │ │       └───────── контейнер ручного возврата
                      │ │ └─ импринтер
                      │ └─── продвинутый мутатрон
                      └───── обычный мутатрон
```

Каждый МЭ-интерфейс одновременно:

1. физически касается своего транспозера;
2. подключён к общей МЭ-сети;
3. касается адаптера OpenComputers, соединённого кабелем с управляющим компьютером.

Порядок граней не важен. У одного транспозера должен быть ровно один соседний
МЭ-интерфейс. `scan` показывает номера и направления сторон.

## Что потребуется

Минимум:

- компьютер OpenComputers с OpenOS;
- два транспозера;
- два МЭ-интерфейса;
- два адаптера OpenComputers для компонентов МЭ-интерфейсов;
- кабель OpenComputers до компьютера;
- одна доступная компоненту база данных OC с хотя бы одной свободной ячейкой;
- один обычный мутатрон Gendustry;
- один продвинутый мутатрон Gendustry;
- один генетический импринтер;
- три отдельных инвентаря, лучше подписанные сундуки;
- постоянное питание и загрузка всех чанков установки;
- один обычный булыжник в общей МЭ на время bind.

В общей МЭ должны находиться исходные принцессы, доступные дроны и расходники.
Мутатронам нужны рабочая подача мутагена и Genetics Labware. В импринтере должен
быть подготовленный шаблон без гена вида, а также Genetics Labware. Шаблон с геном
вида испортит линии, заменяя целевой вид пчелы.

## Роли контейнеров

### Ручной возврат

Только для матки, полученной игроком в продвинутом мутатроне. Перед активацией
новой ручной задачи контейнер должен быть пуст. Уже возвращённая ожидаемая матка
не блокирует запуск `check`.

### Готовые производители

Сюда выдаются финальные матки, которые закрывают выбранные виды сот. Исполнитель
не должен забирать их обратно для рискованных мутаций.

### Источники дронов

Сюда сохраняются вспомогательные линии, нужные для размножения дронов. Это не тот
же инвентарь, что сундук готовых производителей.

Три роли нельзя назначить одному инвентарю. Если используются одинаковые сундуки,
ориентируйтесь на UUID транспозера и сторону из `opencombkeeper scan`; физические
таблички рядом с сундуками сильно снижают вероятность ошибки.

## Подключение

1. Подключите оба МЭ-интерфейса к одной сети.
2. Поставьте каждый интерфейс вплотную к своему транспозеру.
3. С другой стороны каждого интерфейса поставьте адаптер OC и соедините адаптеры
   с компьютером кабелем.
4. Поставьте механизмы вокруг первого транспозера, контейнеры вокруг второго.
5. Подключите базу данных OC к тому же компьютеру.
6. Уберите предметы из девяти локальных слотов обоих интерфейсов и очистите все
   девять конфигурационных запросов.
7. Положите один булыжник в МЭ и выполните `opencombkeeper scan`.
8. Проверьте, что видны два транспозера, два конфигурируемых интерфейса, база,
   три механизма и три контейнера.
9. Запустите `opencombkeeper run` или явно `opencombkeeper bind`.
10. По очереди назначьте три контейнера. После сохранения выполните
    `opencombkeeper topology-check`.

Bind не трогает слоты механизмов и пчёл. Он временно использует девятый запрос
МЭ-интерфейса и одну свободную ячейку базы для дескриптора булыжника.

## Масштабирование

Дополнительный обычный мутатрон или импринтер ставится рядом с транспозером,
который уже имеет собственный связанный МЭ-интерфейс. Если свободных граней нет,
добавляется ещё один полный модуль `транспозер + МЭ-интерфейс + OC-адаптер`.

Программа сохраняет все найденные обычные мутатроны, продвинутые мутатроны и
импринтеры соответствующих типов. Пасеки, анализаторы и пробоотборники
OpenBeekeeper не предлагаются как контейнеры OpenCombkeeper и могут оставаться в
той же компонентной сети.

## Перед реальной работой

Версия 0.2.0 создаёт и проверяет топологию, но физические операции по-прежнему
выполняет машинно-зависимый `/home/.opencombkeeper/hardware.lua`. Он должен быть
реализован по контракту `src/hardware.example.lua` и испытан на одной неценной
линии. Успешный bind сам по себе ещё не доказывает правильность слотов механизмов,
подачи жидкостей и точного экспорта NBT-вариантов пчёл из МЭ.
