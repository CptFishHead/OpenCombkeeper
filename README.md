# OpenCombkeeper

Планировщик и исполнитель селекции пчёл Forestry/Gendustry для получения всех
уникальных видов сот в McSkill HiTech 1.12.2.

Проект решает другую задачу, чем OpenBeekeeper: единицей цели является продукт,
а не вид пчелы или образец гена. Несколько сот одного типа закрываются одним
производителем; для совпадающих продуктов учитывается реальная вероятность.

## Режимы

- `collect` — получить каждую соту хотя бы один раз; линию можно использовать дальше.
- `best` — сохранить живую линию лучшего доступного производителя каждой соты.

В интерфейсе режим `best` называется **«Сохранять лучших производителей»**.

## Быстрый старт планировщика

```sh
python3 -m opencombkeeper.cli plan \
  --catalog data/comb-catalog.json \
  --config examples/mcskill.json \
  --output plan.json
```

План содержит выбранных производителей, цепочки линий, распределение стартовых
принцесс, количество мутаций, критическую глубину и задачи игроку.

Клиентский каталог не доказывает серверные рецепты. Перед игровым запуском план
должен быть сверен с каталогом Forestry через OpenComputers.

## Аппаратная топология

Интерфейс обслуживания повторяет OpenBeekeeper: `scan`, `bind`, `bind-reset`,
`modules`/`topology` и read-only `topology-check`. При первом `run` отсутствие
сохранённой топологии автоматически запускает мастер привязки. МЭ-интерфейсы
сопоставляются с транспозерами запросом одного булыжника, а контейнерам
назначаются понятные роли.

При следующих запусках программа сначала проверяет адреса, стороны и типы
устройств. Временно недоступный компонент не считается доказательством
перестройки. При подтверждённом изменении игрок выбирает повторную проверку,
`rebind` или выход; сохранённая конфигурация не заменяется частичным результатом.

Минимальная физическая схема и список блоков приведены в
[`docs/module-layout.md`](docs/module-layout.md).

## Состояние версии 0.2.0

Готовы детерминированный планировщик, компактный каталог и проверяемый автомат
состояний OpenOS. Адреса компонентов и стороны теперь создаются мастером
топологии. Машинно-зависимые операции транспорта пока реализуются отдельным
`hardware.lua`: без него исполнитель прекращает работу до любого перемещения.
Порядок безопасной установки описан в `INSTALL.md`.
