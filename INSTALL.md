# Установка OpenCombkeeper 0.3.2

## 1. Установить на OpenOS

На компьютере с интернет-картой:

```sh
wget -fq https://raw.githubusercontent.com/CptFishHead/OpenCombkeeper/main/install.lua /home/opencombkeeper-setup.lua && lua /home/opencombkeeper-setup.lua
```

Установщик читает manifest с `main`, но сами файлы загружает из одного
неизменяемого Git commit. Для каждого файла проверяются размер, Adler-32 и
синтаксис Lua. Существующие `/home/.opencombkeeper/hardware.lua`, данные и
сохранённая топология не перезаписываются.

Проверка файлов:

```sh
lua /home/.opencombkeeper/setup.lua check
```

## 2. Подготовить bind

Нужны:

- 8 рабочих модулей, в каждом: OC-адаптер, МЭ-интерфейс, транспозер,
  промышленная пасека, обычный мутатрон, импринтер и локальный сундук;
- 4 пасеки без эмулятора, по одной с Jungle, Desert, Winter и Hell Emulation Upgrade;
- 4 полностью ручных продвинутых мутатрона без транспозеров и OC-подключения;
- отдельный выходной сундук у собственного транспозера, МЭ-интерфейса и OC-адаптера;
- компонент базы данных OC со свободной ячейкой;
- один булыжник в общей МЭ;
- пустые локальные слоты и пустая конфигурация запросов рабочих МЭ-интерфейсов.

Сначала выполните:

```sh
opencombkeeper scan
opencombkeeper bind
opencombkeeper topology-check
```

Bind временно использует девятый запрос интерфейса и одну ячейку базы данных.
Пчёл и слоты механизмов он не изменяет; в пасеках только читает апгрейды из
слотов 3–6. Если bind прерван, выполните `opencombkeeper bind-reset`.

Топология сохраняется атомарно в `/home/.opencombkeeper-data/topology`.
На последующих стартах программа сверяет компоненты, стороны устройств и
сигнатуры климатических апгрейдов. При изменении предлагает повторную проверку
или rebind.

## 3. План

В релиз уже включён `plan.lua` для каталога McSkill: 105 видов сот, 99 лучших
производителей, 114 стартовых линий, 208 мутаций, критическая глубина 13 и 69
ручных задач. Линия получает профиль модуля по климату конечного вида.

Новый план можно собрать на ПК с Python 3.10+:

```sh
python3 -m pip install -e .
opencombkeeper plan \
  --catalog data/comb-catalog.json \
  --config examples/mcskill.json \
  --output plan.json \
  --lua-output plan.lua
```

## 4. Физический транспорт

Команды `scan`, `bind`, `topology` и `topology-check` работают сразу. Реальное
перемещение пчёл намеренно требует машинно-зависимый
`/home/.opencombkeeper/hardware.lua`; его контракт установлен как
`/home/.opencombkeeper/hardware.example.lua`. Без адаптера `run` безопасно
останавливается до первого переноса.

Ручной результат из продвинутого мутатрона возвращается в общую МЭ. Исполнитель
запоминает исходное количество маток требуемого вида и ждёт его увеличения.
Четыре продвинутых мутатрона дают очередь из четырёх одновременно подготовленных
ручных операций; одна матка не может закрыть две задачи одного вида.
