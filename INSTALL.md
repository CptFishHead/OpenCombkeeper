# Установка OpenCombkeeper 0.2.0

## 1. Построить план

На компьютере с Python 3.10+:

```sh
python3 -m pip install -e .
opencombkeeper plan \
  --catalog data/comb-catalog.json \
  --config examples/mcskill.json \
  --output plan.json \
  --lua-output plan.lua
```

До запуска проверьте `startingShortages`, `unreachableCombs` и список ручных
задач в `plan.json`.

## 2. Установить файлы OpenOS

В `/home/.opencombkeeper/` нужны:

- сгенерированный `plan.lua`;
- `src/executor.lua`;
- `src/topology.lua`;
- собственный `hardware.lua` по контракту `src/hardware.example.lua`.

Точку входа `opencombkeeper.lua` можно положить в `/home/bin/`.

## 3. Подготовить привязку

Как и OpenBeekeeper, мастер использует один булыжник для сопоставления
МЭ-интерфейсов с транспозерами. Перед первым запуском нужны:

- один обычный булыжник в общей МЭ;
- свободная ячейка базы данных OpenComputers;
- пустые девять слотов и пустая конфигурация рабочих МЭ-интерфейсов;
- обычный мутатрон, продвинутый мутатрон и импринтер;
- три видимых транспозерам контейнера: ручной возврат, готовые производители и
  источники дронов.

Команда `opencombkeeper scan` только показывает найденное оборудование. Первый
`opencombkeeper run`, если топологии ещё нет, сам запускает bind и просит выбрать
роли трёх контейнеров. Результат сохраняется атомарно в
`/home/.opencombkeeper-data/topology`.

После перестройки используйте `opencombkeeper rebind`. Если bind был прерван,
сначала выполните `opencombkeeper bind-reset`: команда снимает только собственный
запрос маркера и не трогает слоты механизмов.

## 4. Подключить транспортный адаптер

Адаптер обязан проверять фактический результат каждого переноса и атомарно
сохранять состояние. Для `prepare_manual_mutation` он загружает родителей в
продвинутый мутатрон; игрок выбирает результат и возвращает матку в отдельный
контейнер. Для обычной мутации адаптер возвращает распознанный вид матки либо
`genetic_waste`.

Сначала выполните `opencombkeeper topology-check`, затем `status` и пробный `run`
на одной неценной линии. Полный запуск допустим только после проверки адресов,
сторон и слотов непосредственно на сервере. Команда `opencombkeeper check`
дополнительно проверяет ожидаемые результаты активных ручных задач.
